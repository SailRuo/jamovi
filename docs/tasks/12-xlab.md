# P3 · X-Lab 项目管理对接

## 目标

项目管理**放在 X-Lab**，不在 X-Stat 里再做一套看板。X-Stat 保持轻量：只做可视化与统计分析。

本仓库交付的是**文件约定、打开方式、回写关键结果**，不是卡片 UI。

## X-Lab 卡片结构（文档）

一个分析项目 = 1 个分析策略卡片 + 1 个数据归集与清洗卡片 + 多个分析任务卡片。

### 分析策略卡片 ×1

附件：Word，含科学问题、数据来源、分析任务（总量/亚组）、关键结果（完成后追加）。可当模板复用。

### 数据归集与清洗卡片 ×1

与策略分开，避免清洗反复导致同一卡片文件过多。

| 附件 | 内容 |
|---|---|
| 1 | 原始数据文件夹链接 |
| 2 | 归集日志 Word |
| 3 | 合并规范化后的 Excel（文件名含版本） |
| 4 | 清洗+描述后的 `.omv` 元数据（文件名含版本） |

后续分析都调用同一元数据。表格层打扫用 Excel；统计层合规用 X-Stat。

### 分析任务卡片 ×N

客户自定义分组。推荐：简单项目一个 `.omv`；过大则拆成「基础统计 + 生存 + 亚组」，避免过程太长导致软件变慢或崩溃。

每个卡片挂对应 `.omv`（多次迭代用多个附件）。X-Lab 只做备注；混搭由客户定。

### 工作流

说明各分析任务之间的关系（X-Lab 工作流记录）。

## X-Stat 侧任务

- [ ] **T-12-01** 与 X-Lab 约定项目根目录结构（可与 [11](./11-ai-archive.md) 打包结构共用）
- [ ] **T-12-02** 项目菜单「打开」支持从 X-Lab 传入的 `.omv` 路径（协议：命令行参数 / 自定义 URL / 文件关联）
- [ ] **T-12-03** 保存时不破坏 X-Lab 附件相对路径；另存为新版本时文件名加版本号
- [ ] **T-12-04** 「导出结果」默认落到该任务卡片对应的 `exports/`
- [ ] **T-12-05** 可选：把关键图路径、一句结论写回策略卡片「关键结果」（需 X-Lab API）
- [ ] **T-12-06** 文档中的模板 `.omv`（数据替换场景）作为 X-Lab 策略模板附件

## 明确不做（本仓库）

- 卡片、列、看板
- Word 科学问题编辑器
- Excel 多表合并（文档指定 Excel）

## 验收

- 从 X-Lab 任务卡片打开 `.omv` 即进入 X-Stat
- 保存/导出文件出现在该卡片约定目录
- 清洗卡片与分析任务卡片使用同一份元数据 `.omv`

## 依赖

X-Lab 接口与路径规范。P0 项目菜单、数据替换。
