# P2 · 生存分析与 ROC

## 目标

把生存分析做成**逐步升级的策略**，而不是只画一张 KM：

数据规范 →（可选 LASSO 海选）→ 单因素 KM / Cox / ROC → 多因素 Cox + 风险评分 → 时间依赖 ROC / KM 分层 → 验证

## 现状与缺口

| 步骤 | 文档方案 | 缺口 |
|---|---|---|
| 数据规范 | time 连续>0，status 0/1 数值 | 因子标签与底层数值不一致，文档已踩坑 |
| LASSO-Cox | Rj + glmnet + jmvconnect，需系统 R | 无界面；`JAMOVI_ALLOW_ARBITRARY_CODE` 默认关 |
| 单因素 KM / Log-rank | ClinicoPath / jsurvival | 要预装；无批量中位数切分 |
| 单因素 Cox | 单变量用 UI，多变量用 Rj | 无批量、无总表 |
| 单因素 ROC | pROC 脚本 | 无界面 |
| 多因素 Cox | Jsurvival multivariable | **不提供 B（coef）**，风险评分公式难写 |
| 风险评分 | 用 coef 加权求和 | 依赖 B 值输出 |
| 时间依赖 ROC | 模块内 | 需确认预装模块是否包含 |
| 内部 bootstrap / 外部验证 | 文档写「没跑通」 | 需新做或标为未交付 |
| FDR | 暂不考虑 | — |

## 推荐产品形态

不要把长 Rj 脚本交给客户。做成一个 **「生存工作流」模块**，步骤条：

1. 检查数据  
2. 海选（可选 LASSO）  
3. 单因素  
4. 多因素  
5. 风险评分与 ROC  
6. 导出

每步结果留在同一分析里，方法说明同步切换。底层可调用 survival / glmnet / pROC，但 UI 是窗口不是代码。

## 子任务

### 规范与检查

- [ ] **T-09-01** 进入生存前强制检查：time 数值且 >0、无缺失策略、status ∈ {0,1} 且为连续/整型不是名义标签
- [ ] **T-09-02** 一键把「水平 0/1 的名义变量」转成数值 0/1（避免 R 读到 2,1）
- [ ] **T-09-03** 事件数 vs 协变量数警告（文档：事件数 ≥ 自变量×5）

### 单因素

- [ ] **T-09-04** KM + Log-rank：分类因素直接分组；连续因素按中位数（可改四分位）切分
- [ ] **T-09-05** 单因素 Cox 表：Beta、HR、95% CI、p；连续变量用原始值或明确的 Z
- [ ] **T-09-06** 单因素 ROC：AUC、95% CI、Youden cutoff、敏感度/特异度
- [ ] **T-09-07** 批处理接入 [07-batch.md](./07-batch.md)（每指标一张 KM + 总表）

### LASSO 海选

- [ ] **T-09-08** 窗口：选 time/status/候选变量、`lambda.min` vs `lambda.1se`、`set.seed`
- [ ] **T-09-09** 输出非零系数表、把 `lasso_riskscore` 写回数据
- [ ] **T-09-10** 默认 `lambda.1se` 更保守；说明里写清与 `lambda.min` 的差异（文档两段脚本不一致，产品要固定默认并允许切换）

### 多因素与评分

- [ ] **T-09-11** 多因素 Cox：似然比、PH 假定（Schoenfeld）、C-index、独立预后判断（p<0.05 且 CI 不含 1）
- [ ] **T-09-12** **必须输出 coef / B 值**，并生成风险评分列：`Σ(B_i × x_i)`
- [ ] **T-09-13** 风险分组：按 Youden 或中位数切分，写回数据
- [ ] **T-09-14** 时间依赖 ROC（1/2/3 年，时间点可配）
- [ ] **T-09-15** 高低风险 KM + Log-rank
- [ ] **T-09-16** 论文表述模板（可套文档示例句，填入中位生存、HR、p）

### 验证（文档未跑通，单独标范围）

- [ ] **T-09-17** 内部 bootstrap：先做最小可用（C-index 置信区间），失败则界面标明「未启用」
- [ ] **T-09-18** 外部验证：导出评分公式（变量名 + B），新队列「数据替换」后套用同一公式

### 分类结局对照

- [ ] **T-09-19** 单因素 Logistic + ROC（OR 解读），与生存流程并列，避免用户用错终点

## 验收

- 不打开 R 控制台，能从一张合规表走到：单因素总表 → 多因素 → 风险评分 → KM 分层
- 结果里能看到 B 值，计算列公式可复现评分
- status 编码错误时被拦住，而不是静默拟合
- 50 个标志物的单因素 KM 走批处理

## 风险

- ClinicoPath / jsurvival 许可与二次修改
- glmnet 依赖系统 R vs 内置 R
- 任意代码开关的安全策略：工作流模块应自包含，生产环境仍关闭通用 Rj
